1. 프로젝트 개요
--------------------------------------------------------------------------------
 - React 없이 FastAPI 하나로 화면과 API를 모두 제공한다.
   (화면 : Jinja2 템플릿 + CSS + 챗봇용 JavaScript 1개)
 - data 폴더의 와인 데이터를 ChromaDB에 임베딩해 저장하고 유사도 검색을 한다.
 - 제공 기능
     · 와인 정보 검색(벡터 기반, 유사도 점수 표시)
     · 가격/재고 필터
     · AI 소믈리에 챗봇(대화 기록 유지)
     · YouTube 와인 영상 추천
 - 이전 프로젝트의 "추천 리스트 마크다운 파일 저장" 기능은 제공하지 않는다.

3. 처리 흐름
--------------------------------------------------------------------------------
 [임베딩] python vectordb/create_vector_db.py
   wine_brief.csv → 행 1개 = 청크 1개 (60개, source_type = Structured Data)
   wine_detail.md  → 와인 1개 = 청크 1개 (60개, source_type = Unstructured Data)
   → text-embedding-3-small 임베딩 → ChromaDB 저장(코사인 거리)
   · 청크마다 고정 id를 사용하므로 다시 실행해도 중복 저장되지 않는다.
   · 청크 메타데이터
       공통      : name, vintage, region, price, stock, source_type
       상세 문서 : pairing, tasting_note
       필터용    : price_value (가격, 단위: 만원, 미정이면 없음), stock_value (재고량)

 [유사도 검색] GET /search , GET /api/search
   검색어 임베딩 + 가격/재고 조건(where) → ChromaDB 코사인 유사도 검색
   → 와인 단위로 묶어 점수와 함께 표시
   · 조건은 메타데이터로 정확히 걸러진다. 가격 조건을 지정하면 가격 미정 와인은 제외된다.

 [챗봇] POST /api/chat
   chat.js → chat/router.py → run_agent()
     → LLM(gpt-5-nano)이 필요한 도구 선택 → 도구 실행 → 최종 답변
     → search_wine 도구는 질문의 가격/재고 조건을 min_price, max_price,
       in_stock_only 인자로 받아 상세 문서를 검색한다.
     → 대화 기록은 storage/wine_chat.db에 저장(브라우저 쿠키 wine_thread_id로 구분)
     → 답변 마크다운을 HTML로 변환해 응답(원본 HTML 태그는 이스케이프)

9. 이전 프로젝트와 달라진 점
--------------------------------------------------------------------------------
 항목             이전 프로젝트              이번 프로젝트
 ───────────────  ─────────────────────────  ──────────────────────────────
 화면             Streamlit                  FastAPI + Jinja2 + CSS/JS
 도구 실행        MCP stdio 서버             앱 내부 LangChain 도구
 대화 구분        고정 THREAD_ID             브라우저별 쿠키
 CSV 청킹         300자 단위 (8개)           행 단위 (60개)
 상세 문서 청킹   300자 단위 (84개)          와인 단위 (60개)
 유사도 계산      L2 거리(기본값)            코사인 거리
 재실행           청크가 중복 저장됨         고정 id로 덮어씀
 영상 추천        LLM 판단(필요하면)         사용자가 요청할 때만
 추천 리스트 저장 마크다운 파일로 저장       제거 (제공하지 않음)
 가격/재고 조건   벡터 검색에 의존           메타데이터 필터로 정확히 적용
 챗봇 검색 대상   LLM이 source_type 선택     상세 문서만 검색

 변경 이유
 · MCP stdio → 앱 내부 도구
     MCP stdio는 도구를 호출할 때 subprocess를 실행한다. Windows에서
     uvicorn --reload 로 실행하면 subprocess를 지원하지 않는 SelectorEventLoop가
     사용된다. (uvicorn/loops/asyncio.py 에서 확인)
 · 청킹 변경
     기존 방식은 상세 청크 84개 중 17개에 와인 이름이 없어서 검색되어도 어떤
     와인인지 알 수 없었고, CSV는 컬럼명이 첫 청크에만 있었다.
 · 임베딩 텍스트 구성
     상세 문서에서 출처 URL과 마크다운 기호를 빼고 필드를 재구성했다.
     페어링 키워드 기준 상위 5개 정답률이 12/30 → 14/30 으로 소폭 올랐다.
     (질문 6개로 측정한 값이므로 참고용)
 · 영상 검색 조건
     기존 프롬프트로는 요청하지 않은 영상 검색도 실행되어 응답이 느려졌다.
 · 가격/재고 필터
     벡터 검색은 숫자 조건을 구분하지 못한다. 챗봇에 "20만원 이하 와인 3개"를 물었을
     때 가격 미정, 재고 0인 와인이 포함되었다. 숫자 메타데이터 필터를 추가한 뒤에는
     같은 질문에서 조건을 벗어난 와인이 나오지 않았다.
 · 챗봇 검색 대상을 상세 문서로 고정
     LLM이 가격 질문에 페어링 정보가 없는 정형 데이터를 선택하면, 레드 와인을
     화이트라고 하거나 페어링을 지어내는 문제가 있었다. 상세 문서에는 기본정보가
     모두 들어 있어서(60종 값 일치 확인) 상세 문서만 검색해도 정보가 줄지 않는다.
     화면과 API의 검색 대상 선택(source_type)은 그대로 유지했다.


10. 사용하지 않아 제거한 항목

     다시 필요하면 pip install 로 설치한 뒤 requirements.txt를 갱신한다.
 · .env 키 : HUGGINGFACE_ACCESS_TOKENS, LANGSMITH_API_KEY, WEATHER_API_KEY
     같은 값이 D:\aiproject\.env 에 있다.
 · 벡터 DB 메타데이터 : category, source, row


11. 주의사항
--------------------------------------------------------------------------------
 · create_vector_db.py 를 다시 실행했다면 서버를 재시작해야 한다.
     실행 중인 서버는 벡터 인덱스를 메모리에 들고 있어서, 재시작 전까지는 이전
     벡터로 검색한다. (재임베딩 후 문서는 새 내용, 점수는 이전 값이 나오는 것을
     확인함) create_vector_db.py 실행은 파일을 수정하는 것이 아니므로 --reload도
     동작하지 않는다.
 · 벡터 검색의 한계
     · 가격/재고 필터는 정확하지만, 지역 필터는 제공하지 않는다. "재고 있는 보르도
       와인"처럼 물으면 재고 조건은 지켜지지만 보르도 4종 중 일부만 찾을 수 있다.
     · "가장 저렴한 와인" 같은 정렬은 지원하지 않는다. 검색된 후보 안에서 LLM이
       고르는 것이므로 항상 맞는다고 보장할 수 없다.
     · 음식 페어링은 의미가 가까운 것을 찾을 뿐이다. 해산물 질문에 해산물 페어링이
       아닌 와인이 나올 수 있다. (답변에는 DB의 실제 페어링이 표시됨)
     · 기본정보(CSV) 행은 글이 짧아서 전체 검색의 맛/음식 질문에도 간혹 상위에
       나온다. 맛/음식 검색은 검색 대상을 "상세 설명"으로 하면 더 정확하다.
 · langchain-community 경고
     실행 시 "being sunset" DeprecationWarning이 출력될 수 있으나 동작에는 문제가
     없다. (TextLoader, CSVLoader, YouTubeSearchTool 사용)
 · PyCharm import 설정
     코드는 backend 폴더를 기준으로 import 한다. (예: from common.config import BASE_DIR)
     그래서 .idea/fastapiproject.iml 에 backend를 Sources Root로 등록해 두었다.
     빨간 밑줄이 남아 있으면 backend 폴더 우클릭 → Mark Directory as → Sources Root
     common, chat, search 등에 "Install package"가 표시되어도 누르지 말 것. 프로젝트 폴더와
     같은 이름의 무관한 PyPI 패키지가 설치될 수 있다. 이전 프로젝트에서도 같은 방식으로
     설치된 agent-builder가 LangChain을 다운그레이드했다. (project_install.txt 참고)
